# 已知局限（LIMITATIONS）

按阶段追加。每条写明影响范围和对应的 ADR。

## 数据采集（S1）

1. **AkShare 1.18.97 取不到申购费率**：`fund_fee_em(indicator="申购费率")` 恒返回空表。原因是 AkShare 按东方财富费率页的小标题取表，但代码只认「申购费率（前端）」，页面现在的标题是「申购费率」。本项目不修改 AkShare 源码，改从招募说明书的费率表解析申购费分档（ADR-027）。因此申购费数据的时效等于最新一版招募说明书，而不是销售平台的实时展示；表格版式无法解析的份额记为缺口。
2. **AkShare 1.18.97 的人事公告接口在 0 条结果时报错**：`fund_announcement_personnel_em` 对没有公告的基金抛 `Length mismatch`，流水线把它当作空结果（ADR-027）。
3. **东方财富接口是非官方接口**：公告列表（JJGG）、净值、排行等接口没有稳定性承诺，字段可能变化；流水线固定 AkShare 版本、本地缓存原始结果，接口变化时直接报错而不是静默补值。
4. **披露 PDF 取自东方财富转载件**：证监会基金电子披露网站从本机命令行不可达（PLAN §2.1），PDF 使用 `pdf.dfcfw.com` 上由基金管理人发布的转载件，MANIFEST 记录 URL 与 sha256。
5. **LOF 按场外份额收录**：160219、161035 是 LOF，只使用场外 A/C 份额的净值和费率，不涉及场内交易价格（ADR-030）。

## 检索（S4）

以下数字都来自 test 集检索评测，n=72（79 题去掉 7 道 unanswerable），原文 `reports/retrieval/20260929T090548Z/`。

1. **绝对水平不高**：最终配置 hybrid_rerank 的 hit@5 = 0.653、nDCG@10 = 0.532。命中口径较严（要求 doc_id 相同且引文 50% 连续片段落在块里），同一条款出现在年报和招募说明书时只算其一，所以数字低于「找到能回答问题的内容」的比例（后者未另行度量）。
2. **纯 RRF 混合检索不如单独 BM25**：hybrid（RRF，k=60）nDCG@10 0.3633，bm25 0.3854，点估计低 0.022（未做配对 CI）。观察到的解释是 bge-small-zh-v1.5 在 20 只基金、文档大段雷同的语料上区分力弱（vector 单路 0.2004），等权 RRF 被它拖累；该解释未做消融验证。有效的提升来自重排（hybrid → hybrid_rerank +0.169）（ADR-039）。
3. **持仓类问题检索很弱**：holdings（11 题）hybrid_rerank nDCG@10 只有 0.126。持仓表格块的入库方式不改（ADR-039）；持仓题的主路径是 `run_fund_sql` 查 `holdings_top10` 表，文档检索只作补充。原因（持仓表碎片、表格行只有数字）是观察到的现象，未验证。
4. **实体过滤默认关闭**：dev 上关更好，test 上开 +0.022 但 95% CI [−0.010, +0.065] 含 0，按协议不据 test 改配置（ADR-038）。S5 `search_fund_documents` 的 `fund_codes` 由 Agent 显式传入，与该开关独立。
5. **重排在 CPU 上慢**：20 个候选每次约 2.7–4.6 秒，只适合离线评测；线上需要 GPU、缩小候选数或换更小的重排模型（S12–S13 评估）。
6. **样本量小**：dev 30 题、test 72 题，按 topic 拆分后每类只有 8–13 题，CI 很宽。
