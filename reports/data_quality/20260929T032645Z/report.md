## 5. 区间收益：来源方 period_returns vs 用净值自算

- 分母：**276 对**（份额 × 区间，区间为 1m/3m/6m/1y/2y/3y/ytd；来源方为空值的、以及份额成立不满该区间的不计入；1w 与成立来不比）。起点取区间起始日当天或之前最近的净值日。
- 三种自算口径与来源方的差（百分点）：

| 口径 | 在 ±0.01pp 内 | 最大绝对差 |
|---|---|---|
| reinvest：单位净值之比 × Π(1 + 每份分红 / 除息日净值) | **276/276** | 0.005 |
| unit：单位净值之比（不含分红） | 265/276 | 13.821 |
| chain：Π(1 + 日增长率) | 69/276 | 0.466 |

- **解释**：来源方的区间收益是「分红按除息日净值再投资」的口径，reinvest 自算全部吻合（容差 0.01pp 对应来源保留两位百分数）。unit 口径差异集中在区间内有分红的 11 对（`pairs_with_dividends`），分红使单位净值下降，所以只看单位净值会低估，最多低 13.8 个百分点。chain 口径的偏差来自来源方的日增长率只保留两位百分数，几百个交易日连乘后误差累积到最多 0.47pp。S5 的 `calc_fund_return` 应采用 reinvest 口径（PLAN §5 S5「正确处理分红」），并以此处结果作为对照。

## 7. 口径说明（数据问题，已报告，未修正）

- `data/universe.yaml` 的 `scale_yi` 取自 `fund_overview_em` 的「净资产规模」。B1 用季报核对发现，它是**主代码（A 类）份额**的规模，不是全部份额合计。例如 003095：A 类 12,735,565,685.72 元 ≈ 127.36 亿，与 overview 完全一致；C 类另有 12,034,814,036.87 元。基金合计规模以 `fund_scale` 表（季报各份额相加）为准。「≥2 亿」门槛不受影响（合计 ≥ A 类），但 universe.yaml 注释里「全部份额合计」的说法不准确。universe 已冻结，所以没有改文件，记在 `data/CHANGELOG.md`，是否更正注释由统筹和用户决定。

## 8. 修正记录（为什么有早期 run）

早期 run 与本 run 的差异全部来自解析代码修正，均有单测：
1. AkShare 持仓接口的「序号」是跨季度流水号（Q2 从 25 开始），改为在每个报告期内按占净值比例重新排名取前 10（`holdings_top10` 从 400 行变为 1200 行）。
2. 申购费表：识别「引导语最后一句」判断养老金优惠表；支持 A/C 合表、养老金与其他投资者两列并列、无表格线正文三种版式。
3. 经理简介表：表头跨行、跨页续表（最多 3 页）、「基金经理助理」行排除。
4. 季报前十持仓表：标题在页末、表格在下一页；表头跨 3 行；合并单元格产生的空列。
5. 区间收益比对增加 reinvest 口径；持仓比对从按排名改为按证券代码。
